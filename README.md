V106.6｜跨尺寸切換後棋盤版型殘留修正

使用者回報：先進入 6×6 或 9×9 任務，再返回 4×4 任務時，4×4 棋盤會沿用先前棋盤的行列配置／尺寸，造成棋盤被壓扁或留有大面積空白。

檢查結果：
- render() 原本只清除 grid 的 width、height、aspectRatio。
- 沒有清除 gridTemplateColumns、gridTemplateRows、display 等 inline styles。
- 也沒有在每次重繪時統一清除棋盤本身的 className。
- 例如 9×9 直排留下的 1 欄 × 9 列配置，可能污染後續 4×4 橫排顯示。

修正方式：
- 每次 render() 開始時先清空棋盤內容。
- 將棋盤 className 重設為空。
- 移除整個 style attribute，清除所有前一關殘留的 inline styles。
- 各關卡原有 render 分支接著重新指定自己的 class 與尺寸／行列設定。
- 更新資源版本號至 v106.6，避免瀏覽器沿用舊快取。

本次修改範圍：
- 僅修改 js/app.js 的 render() 棋盤初始化區塊。
- 不修改題目、標準答案、關卡內容、作答邏輯、提示、筆記或進度。
- 不修改語言切換及樹屋按鈕。

驗證紀錄：
- Node.js JavaScript 語法檢查。
- 檢查 render() 已清除 className 與整個 style attribute。
- 確認 4×4、6×6、9×9 各棋盤分支仍自行設定 className／版型。
- ZIP 完整性檢查。
- 實際裝置的跨尺寸切換仍需使用者驗收。
